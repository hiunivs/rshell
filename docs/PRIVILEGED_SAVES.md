# 受保护文件与管理员保存

RShell 内建编辑器默认使用当前本机用户或 SSH 登录用户的权限保存文件。SSH 终端中执行过 `sudo` 不会改变 SFTP 子系统的身份，因此普通用户通常不能直接在 `/etc` 创建临时文件或替换目录项。

## 保存行为

普通保存会：

1. 解析文件的真实路径，编辑符号链接时保留链接本身；
2. 比较打开文件时记录的 SHA-256，发现外部修改时停止并要求明确确认；
3. 在目标目录创建不可预测且排他创建的私有临时文件；
4. 写入并同步内容，保留原文件的所有者、组和权限；
5. 使用原子重命名替换目标；不兼容覆盖式 rename 的 SFTP v3 服务会自动使用兼容流程；
6. 保存后再次校验内容摘要。

当前 SSH 用户没有目标目录写权限时，编辑器会显示“管理员保存”窗口。也可以从编辑器的“文件 → 以管理员权限保存…”主动打开。

管理员保存会先把内容写入 SSH 用户家目录下权限为 `0600` 的随机临时文件，然后通过一个固定、内联的 shell 流程执行 `sudo`：

- sudo 密码只通过 SSH 命令通道的标准输入发送，不会放入命令行、日志、配置文件或系统进程参数；
- 在 sudo 内部再次比较原文件摘要，避免等待输入密码期间覆盖其他程序的修改；
- 复制原文件元数据（包括远端 `cp --preserve=all` 支持的 ACL、扩展属性和安全上下文），再恢复 owner、group 和 mode；
- 校验上传内容和替换后内容的 SHA-256；
- 同步临时文件后在目标目录内原子替换；替换前任一步失败都会保留原文件；
- 保存 `/etc/sudoers` 或 `/etc/sudoers.d/*` 前强制执行 `visudo -cf`，保存 SSH 服务主配置 `sshd_config` 前执行 `sshd -t`，保存 Nginx 主配置 `nginx.conf` 前执行 `nginx -t`；校验失败不会替换。

如果密码留空，RShell 只尝试已有的 sudo 凭据缓存或服务器现有的免密规则，不会弹出终端密码提示。

## 远端要求

管理员保存面向 Unix/Linux SSH 主机，需要：

- SFTP 可用，且 SSH 用户家目录可写；
- `/bin/sh`、`sudo`、`cp`、`mv` 和 `sync`；
- `sha256sum`、`shasum` 或 `sha256` 中至少一个；
- 修改 sudoers、SSH 服务主配置或 Nginx 主配置时，必须分别安装 `visudo`、`sshd` 或 `nginx` 作为语法校验器。

禁止仅为了 RShell 给普通用户配置 `NOPASSWD: /bin/sh`、`NOPASSWD: ALL`，也不要修改 `/etc` 目录为普通用户可写。管理员保存尊重服务器现有的 sudo 策略；用户本身没有目标操作的 sudo 权限时，服务器仍会拒绝。

启用了 `requiretty`、禁用了非交互式 sudo，或使用 `doas` 而非 `sudo` 的主机暂不支持该流程。此时应使用终端中的 `sudoedit` 或组织已有的配置管理工具。

## 冲突处理

文件在打开后被其他程序修改时，RShell 默认不覆盖，并显示冲突确认框。“仍然覆盖”会跳过旧摘要比较，但仍执行临时文件、同步、元数据保留和原子替换。应先确认远端修改不需要保留，再执行覆盖。

## 本机文件

本机普通文件采用同样的摘要校验、符号链接处理、权限保留和原子替换。RShell 不自行保存或复用本机管理员密码；本机受系统保护的文件请使用 macOS 的 `sudoedit` 或 Windows 管理员工具。
